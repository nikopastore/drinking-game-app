# SipWiki baseline codebase audit — 2026-09-01

**Repository:** `nikopastore/drinking-game-app`  
**Scope:** Full-repository audit (not a PR diff). One pass.  
**Product inferred from code:** SipWiki (`sipwiki.app`) — a drinking-game encyclopedia, cocktail recipes, party planner, and live “AI referee” companion. Not a home-services / contractor / National Planning Group product.  
**Auditor note:** The request named “National Planning Group”; this tree is SipWiki. Findings below are about the code that is actually here.

---

## Executive summary

SipWiki is a **single Next.js 16 App Router app** (not a monorepo) with static game/cocktail catalogs, optional Supabase for social/PII features, and two unauthenticated paid-LLM APIs. There is **no payments processor**, **no admin app**, **no file-upload pipeline**, and **no CI**.

The highest-confidence issues are:

1. **Unauthenticated LLM endpoints** (`/api/chat`, `/api/game-finder`) with client-controlled prompts and an in-memory rate limiter that does not hold across Vercel isolates.
2. **Supabase `SECURITY DEFINER` RPCs** that take a target `user_id` and never check `auth.uid()`, plus a `games` table created **without RLS**.
3. **`user_profiles` is world-readable**, including `phone_number` if that column is ever populated.

No live secrets (API keys, service-role keys) were found in the repo. No Critical RCE / auth-bypass-to-admin / payment-theft issue was confirmed in application code. High issues are real and worth fixing before relying on Supabase social features or leaving the AI APIs publicly billed.

### Trust boundaries

- **Public, unauthenticated:** all catalog pages, `/api/mcp` (full catalog), `/api/chat`, `/api/game-finder`, anonymous email insert, anonymous ratings insert (schema).
- **Authenticated (anon key + RLS):** comments, submissions, favorites, cabinets, contact hashes, friendships.
- **Server-only:** OpenAI and Gemini keys. Chat/game-finder still callable by anyone who can hit the deployment.

## Critical / High detail with evidence

### No Critical findings in application code

There is no admin surface, no Stripe/webhook handler, no service-role key, and no confirmed remote code execution in first-party TypeScript. Schema and LLM-cost issues below are **High**, not Critical, because they require either applying `schema.sql` as-is or sending traffic to billed APIs.

### H1 — `/api/chat` accepts attacker-controlled system prompts

`AIChatFAB` posts the in-memory game object to the API:

```43:51:src/components/AIChatFAB.tsx
      const res = await fetch("/api/chat", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          gameName: game.name,
          rules: game.rules_text,
          message: userMessage,
          history: chatHistory,
        }),
```

The route interpolates those fields into the system message and sends them to OpenAI:

```47:61:src/app/api/chat/route.ts
function getSystemPrompt(gameName: string, rules: string): string {
  return `You are the official referee for "${gameName}". You know the rules inside and out.

RULES:
${rules}
...
```

`rules` is validated only as `z.string().max(10000)`. CORS in `src/lib/cors.ts` allowlists `sipwiki.app` / localhost; **non-browser clients omit `Origin` and are still served**. `checkRateLimit` uses a process-local `Map` (`src/lib/rateLimit.ts`), which resets per serverless instance.

**Impact:** Prompt injection (ignore referee / ignore safety copy), prompt theft, and unbounded OpenAI spend.

### H2 — `/api/game-finder` is an unauthenticated Gemini bill

The route is public POST. Catalog grounding and slug validation in `src/lib/gameFinder.ts` (`validateGeminiRecommendations`) are solid mitigations against hallucinated/off-catalog content. Residual risk is **cost and availability**, not data exfiltration.

### H3 — `find_friends` / favorite RPCs are IDORs

```299:314:supabase/schema.sql
CREATE OR REPLACE FUNCTION find_friends(p_user_id UUID)
RETURNS TABLE (
  friend_id UUID,
  display_name TEXT,
  avatar_url TEXT
) AS $$
  SELECT DISTINCT
    up.id as friend_id,
    up.display_name,
    up.avatar_url
  FROM user_contacts uc
  ...
  WHERE uc.user_id = p_user_id
```

`LANGUAGE sql SECURITY DEFINER` with no `auth.uid()` predicate. `toggle_favorite(p_user_id, ...)` can insert/delete another user’s rows. `useFavorites.ts` uses table RLS (safer), but PostgREST still exposes the RPCs.

`src/lib/contacts/useContacts.ts` calls `find_friends` with the signed-in user’s id — the client is honest; the database is not enforcing that.

### H4 — Vote RPCs bypass `comment_upvotes`

```174:181:supabase/schema.sql
CREATE OR REPLACE FUNCTION increment_comment_upvotes(comment_uuid UUID)
RETURNS void AS $$
BEGIN
  UPDATE comments
  SET upvotes = upvotes + 1
  WHERE id = comment_uuid;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

`CommentSection` inserts into `comment_upvotes` then calls this RPC. A raw `rpc('increment_comment_upvotes')` skips the unique vote table.

### H5 — `games` table has no RLS

```6:21:supabase/schema.sql
CREATE TABLE IF NOT EXISTS games (
  id TEXT PRIMARY KEY,
  ...
);
```

RLS is enabled later for comments, ratings, submissions, etc. **`games` is never `ENABLE ROW LEVEL SECURITY`**. In Supabase the anon role typically has table grants; without RLS those grants are the access policy.

### H6 — Public profiles include phone numbers

```254:256:supabase/schema.sql
CREATE POLICY "Anyone can read user profiles"
  ON user_profiles FOR SELECT
  USING (true);
```

`UserProfile` in `src/types/index.ts` includes `phone_number`. `fetchProfile` uses `select("*")`.

## Suggested `BUGBOT.md` rule updates

Created `.cursor/BUGBOT.md` with rules derived from these findings (not generic OWASP copypasta):

- Never put catalog rules in an LLM system prompt from the client; look up by slug.
- Treat serverless in-memory rate limits as best-effort only.
- Every `SECURITY DEFINER` function must check `auth.uid()` and set `search_path`.
- Every new table must enable RLS in the same migration; public-read tables must not include PII columns.
- Do not add world-writable `INSERT`/`UPDATE` policies for integrity-sensitive tables.
- Auth redirect targets must be relative same-origin paths.
- MCP/CORS `*` is only acceptable for public catalog JSON, and must not grow to authenticated routes.
